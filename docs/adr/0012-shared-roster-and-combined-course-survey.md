# ADR 0012: 共通名簿と講習別アンケートの分離

- 状態: 採用
- 日付: 2026-08-18
- 関連: ADR 0005、0006、0011

## 背景

生徒・講師の在籍情報、講師対応科目、通常授業の担当は講習ごとには大きく変わらない。
一方、開校日、必要授業回数、生徒・講師の不可時間、集団授業、配置結果は講習ごとに
異なる。すべてを各プロジェクトのExcelで繰り返し入力すると、転記とファイル選択が増え、
どれが最新の名簿か判断しにくい。

## 決定

- `%LOCALAPPDATA%/SummerScheduler/workspace/生徒・講師_基本情報.xlsx`を、講習に
  依存しない利用者ローカルの正本とする。
- 共通ブックは「生徒」「講師」「科目」「講師対応科目」「通常授業」の5シートとする。
  生徒・講師IDは空欄でも取込み時に安定IDを採番し、姓と名は別列で保持する。
- 在籍はXlsxWriter 3.2.9以降で生成するネイティブのセル内チェックボックスで入力し、
  退籍者を削除せず末尾・灰色で保持する。基礎値は`TRUE`／`FALSE`とし、行には
  「在籍」「退籍」の文字を置かない。Microsoft 365／Excel 2024以降ではワンクリックで
  操作でき、古いExcelでは`TRUE`／`FALSE`として互換表示される。読込みは従来どおり
  openpyxlを使用し、旧形式の`☑ 在籍`／`☐ 退籍`も受け付ける。
- 生徒・講師の在籍列はA列に置く。必須入力セルは薄い黄色とし、姓を入力した新規行では
  ID候補、チェックあり、最大連続2、空きコマなしを数式で表示する。ID候補は非表示の
  補助シートにある未使用IDを入力順に参照し、複数行へ同一IDを割り当てない。アプリ取込み
  時には数式を信頼せず、既存IDとの衝突を検証して正式値へ確定する。旧列順は互換読込みする。
- 新規プロジェクト作成時に共通名簿を検証し、Student、Teacher、Subject、
  TeacherQualification、RegularLessonProfileを`.jukuschedule`へsnapshotする。
  既存プロジェクトを開くだけでは過去のsnapshotを自動変更せず、ホームの
  「この講習へ反映」を明示操作した場合だけ更新する。
- 通常授業の担当、優先度、1対1必須は`regular_lesson_profiles`へ保存する。講習ごとの
  `lesson_requests.required_sessions`とは分離し、アンケート取込み時に制約snapshotとして
  コピーする。
- アプリから生成したGoogleフォームの生徒回答と講師回答は2ファイルを同時選択し、
  氏名・学年・在籍区分・科目・回数・不可時間を一括検証できるようにする。
- 基本情報にない在籍生・講師はエラー、フォームで体験生と明示された未登録生徒は警告とし、
  体験生だけを当該プロジェクト内へ自動登録する。
- 反映した2原本と、正規化受講希望・要確認一覧を含む統合xlsxをBLOBとして
  `.jukuschedule`へ保存する。再取込みは同じ種別のsnapshotを置換し、ImportBatchと
  AuditLogは残す。
- 既存の1ファイルずつの列マッピング・差分取込みは、独自様式と過去ファイルのために
  維持する。
- 講師の公平性は、最終の任意目的で「担当コマ数」ではなく「勤務可能コマ数に対する
  参加割合」の講師間差を最小化する。整数CP-SATでは割合の差を交差積で表す。これは
  未配置、講師希望、稼働講師枠、希望日時、既存配置保持より後であり、ハード制約や
  上位目的を犠牲にしない。

## 互換性と安全性

- `.jukuschedule`は引き続き1ファイル1 SQLiteで、Student／Teacher等のproject snapshotを
  内包する。共通Excelがなくても既存プロジェクトは開ける。
- schema変更はAlembic `20260818_0008`で追加テーブルだけを作る。既存列の削除・意味変更は
  行わず、既存のmigration前backupを使用する。
- 時間割配置済みプロジェクトでは、受講希望を置換する一括アンケート反映を拒否する。
  既存Assignmentを暗黙に削除しない。
- 共通Excel、アンケート原本、統合xlsx、`.jukuschedule`、backupは個人情報を含み得る。
  外部送信やテレメトリは追加せず、Gitの追跡対象にも含めない。

## 影響

ADR 0011の「現在開いているプロジェクトから次の講習へ人員を継承する」は後方互換の
fallbackとして残すが、画面から作る新規プロジェクトでは本ADRの共通名簿を優先する。
過去の講習を再現するため、既存プロジェクトを開いただけで最新名簿へ自動同期しない。
