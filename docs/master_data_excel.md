# `master_data.xlsx` 仕様

## 1. 位置づけ

この文書はマスターデータの一括入出力形式を説明する。全体の機能仕様と制約は
[`specification.md`](specification.md)を参照する。

本ブックは生徒・講師の日時アンケート、集団授業、固定Assignment、時間割結果を
扱わない。それらはPhase 3以降の別テンプレート・取込みフローで実装する。

> 現在の主導線は、ホームから開く講習共通の`生徒・講師_基本情報.xlsx`である。
> 共通ブックは「通常授業」シートを持ち、講習ごとの必要授業回数を持たない。本書の
> `master_data.xlsx`は既存プロジェクトとの互換、一括移行、詳細編集のために残す
> プロジェクト単位形式である。2つを同じ正本として同時編集しない。

## 2. ブック共通仕様

- ファイル拡張子は`.xlsx`とする。
- シートは「生徒」「講師」「科目」「講師対応科目」「受講希望」の5枚をこの順で持つ。
- 1行目は日本語ヘッダーとする。
- 2行目には架空の例示行を出力する。
- 全シートの先頭列は「例示行」とする。「はい」の行は取込み対象外である。
- 空行は無視する。
- ヘッダーを固定し、オートフィルターを設定する。
- ヘッダーのコメントに入力説明を持たせる。
- 真偽値、整数、学校段階、参照IDには可能な範囲でExcelの入力規則を設定する。
- 入力可能範囲として最大10,000行目まで入力規則を設定する。
- IDと科目コードは文字列で入力する。先頭ゼロを保持する必要があるIDは、Excel上でも
  文字列として扱う。
- 真偽値は「はい」「いいえ」を推奨する。取込みでは`true / false`、`1 / 0`、
  `有効 / 無効`等の定義済み表現も正規化するが、新規ブックでは日本語表現を使う。

空欄にした場合、次の既定値を取り込む。

| シート | 列 | 空欄時の値 |
|---|---|---|
| 生徒 | 標準最大連続コマ数 | `2` |
| 生徒 | 空きコマ許可 | `いいえ` |
| 生徒 | 有効 | `はい` |
| 講師 | 空きコマ許可 | `いいえ` |
| 講師 | 有効 | `はい` |
| 科目 | 有効 | `はい` |
| 講師対応科目 | 指導可能 | `はい` |
| 受講希望 | 担当講師優先度 | `3` |
| 受講希望 | 1対1必須 | `いいえ` |

新しく出力するテンプレートでは、空欄を許可しない入力必須列のヘッダー末尾に
「（必須）」を表示する。以前の「（必須）」がないヘッダーも引き続き取り込める。

「任意」はセルを空欄にできることを意味する。シート構造としては任意項目のヘッダーも
必要であり、列そのものを削除してはならない。未定義シート・列は警告して無視する。

## 3. 生徒シート

一意キーは「生徒ID」である。

| 列名 | 必須 | 型・範囲 | 内容 |
|---|---:|---|---|
| 例示行 | 任意 | 真偽値 | 「はい」の行は取込み対象外 |
| 生徒ID | 必須 | 文字列 | `.jukuschedule`内で一意の安定ID |
| 氏名 | 必須 | 文字列 | 生徒氏名 |
| 学年 | 必須 | 選択値 | `小1`～`小6`、`中1`～`中3`、`高1`～`高3` |
| 標準最大連続コマ数 | 必須 | 1以上の整数 | 通常許可する最大連続コマ数。空欄は2 |
| 空きコマ許可 | 必須 | 真偽値 | 同日内の空きコマ例外。空欄は「いいえ」 |
| 備考 | 任意 | 文字列 | 任意の備考 |
| 有効 | 必須 | 真偽値 | 「いいえ」は使用停止。空欄は「はい」 |

既存と別IDで同じ氏名がある場合は、同姓同名として警告する。名前だけで既存生徒を
特定せず、生徒IDを使用する。

## 4. 講師シート

一意キーは「講師ID」である。

| 列名 | 必須 | 型・範囲 | 内容 |
|---|---:|---|---|
| 例示行 | 任意 | 真偽値 | 「はい」の行は取込み対象外 |
| 講師ID | 必須 | 文字列 | `.jukuschedule`内で一意の安定ID |
| 氏名 | 必須 | 文字列 | 講師氏名 |
| 空きコマ許可 | 必須 | 真偽値 | 同日内の空きコマ例外。空欄は「いいえ」 |
| 備考 | 任意 | 文字列 | 任意の備考 |
| 有効 | 必須 | 真偽値 | 「いいえ」は使用停止。空欄は「はい」 |

既存と別IDで同じ氏名がある場合は、同姓同名として警告する。名前だけで既存講師を
特定しない。

## 5. 科目シート

一意キーは「科目コード」である。

| 列名 | 必須 | 型・範囲 | 内容 |
|---|---:|---|---|
| 例示行 | 任意 | 真偽値 | 「はい」の行は取込み対象外 |
| 科目コード | 必須 | 文字列 | `.jukuschedule`内で一意の安定コード |
| 表示名 | 必須 | 文字列 | 日本語の表示名 |
| 学校段階 | 必須 | 選択値 | `小学校`、`中学校`、`高校`のいずれか |
| 並び順 | 必須 | 1以上の整数 | 一覧で使用する順序 |
| 有効 | 必須 | 真偽値 | 「いいえ」は使用停止。空欄は「はい」 |

「高校・数学一般」と「高校・数学III」は別の科目コードであり、資格を相互に自動推定
しない。

## 6. 講師対応科目シート

一意キーは「講師ID」と「科目コード」の組合せである。

| 列名 | 必須 | 型・範囲 | 内容 |
|---|---:|---|---|
| 例示行 | 任意 | 真偽値 | 「はい」の行は取込み対象外 |
| 講師ID | 必須 | 文字列 | 講師シートまたは既存DBに存在するID |
| 科目コード | 必須 | 文字列 | 科目シートまたは既存DBに存在するコード |
| 指導可能 | 必須 | 真偽値 | 科目ごとの担当可否。空欄は「はい」 |
| 備考 | 任意 | 文字列 | 任意の備考 |

存在しない講師ID、科目コードはエラーとする。資格は各科目について明示し、学校段階や
類似科目から自動推定しない。

## 7. 受講希望シート

一意キーは「生徒ID」と「科目コード」の組合せである。

| 列名 | 必須 | 型・範囲 | 内容 |
|---|---:|---|---|
| 例示行 | 任意 | 真偽値 | 「はい」の行は取込み対象外 |
| 生徒ID | 必須 | 文字列 | 生徒シートまたは既存DBに存在するID |
| 科目コード | 必須 | 文字列 | 科目シートまたは既存DBに存在するコード |
| 必要授業回数 | 必須 | 1以上の整数 | 必要な個別授業回数 |
| 通常担当講師ID | 任意 | 文字列 | 優先度5の場合は必須 |
| 担当講師優先度 | 必須 | 1～5の整数 | 空欄は3。5は通常担当講師固定のハード制約 |
| 第1希望講師ID | 任意 | 文字列 | 科目ごとの第1希望 |
| 第2希望講師ID | 任意 | 文字列 | 科目ごとの第2希望 |
| 第3希望講師ID | 任意 | 文字列 | 科目ごとの第3希望 |
| 1対1必須 | 必須 | 真偽値 | 空欄は「いいえ」。「はい」はハード制約 |
| 最大連続コマ数上書き | 任意 | 1以上の整数 | 空欄なら生徒の標準値を使用 |
| 空きコマ許可上書き | 任意 | 真偽値 | 空欄なら生徒の標準値を使用 |
| 備考 | 任意 | 文字列 | 任意の備考 |

次はエラーとする。

- 生徒ID、科目コード、講師IDが取込みブックまたは既存DBに存在しない
- 必要授業回数が1未満
- 優先度が1～5以外
- 優先度5で通常担当講師がない
- 優先度5の通常担当講師が当該科目を指導不可
- 無効化済み講師を既存値から変更して新規選択する
- 同一生徒・同一科目の重複

次は警告とし、確認後の反映を許可する。

- 優先度1～4の通常担当講師が当該科目を指導不可
- 希望講師が当該科目を指導不可
- 第1～第3希望で同じ講師が重複

通常担当講師と希望講師が同じであること自体は、マスター仕様により許可する。

### 7.1 ID入力と名前選択の使い分け

「講師対応科目」と「受講希望」には、参照するID・科目コードごとに青色の入力補助列を
配置する。

- IDまたは科目コードが分かる場合は、従来どおりID・コード列へ直接入力する。隣の
  「名前（確認）」または「科目名（確認）」へ対応する表示名が自動表示される。
- 名前から入力する場合は「名前から選択」列のプルダウンで選ぶ。左の正式なID・コード
  列へ値が自動表示される。
- 科目コードの隣には科目名が表示されるため、例えばコードだけでなく
  「高校・日本史」のような表示名を目視確認できる。
- 同姓同名が2件以上ある場合は誤選択を防ぐためIDを自動決定しない。その場合はIDを
  直接入力し、「名前（確認）」で対象者を確認する。
- 自動表示された数式列は削除しない。名前から選んだ場合はExcelで再計算された状態で
  保存してからアプリへ取り込む。

青色の補助列は新しいテンプレートで利用できる任意列である。以前に出力した補助列の
ないブックも、従来どおりID・コード列を使って取り込める。

## 8. プレビューと差分判定

取込みはDBを変更する前に、次を含む`ImportPreview`を作成する。

- 取込み元パスと対象project ID
- 正規化済みのシート名、Excel行番号、値
- 行ごとの`new`または`update`
- シートごとの新規件数と更新件数
- シート、行番号、列名、severity、messageを持つissue

差分キーは次のとおりである。

| シート | 差分キー |
|---|---|
| 生徒 | 生徒ID |
| 講師 | 講師ID |
| 科目 | 科目コード |
| 講師対応科目 | 講師ID + 科目コード |
| 受講希望 | 生徒ID + 科目コード |

未知のシート・列、同姓同名、指導不可の希望等は警告とする。必須シート・列欠落、
型・範囲不正、シート内キー重複、参照不整合、優先度5違反等はエラーとする。
エラーが1件でもあるpreviewは反映できない。

## 9. 反映とrollback

利用者がpreviewを確認した後、5シートを次の依存順で同じSQLAlchemy transactionへ
反映する。

1. 生徒
2. 講師
3. 科目
4. 講師対応科目
5. 受講希望

既存キーは更新し、未登録キーは新規作成する。反映中のflushまたはcommitで例外が
発生した場合はtransaction全体をrollbackし、先行シートだけを残さない。

出力も同じディレクトリの一時ファイルへブックを保存し、成功後に目的パスへ
`os.replace`する。Windowsで出力先をExcelが開いている場合等、置換できないときは
失敗を明示し、不完全な目的ファイルへ切り替えない。

## 10. 個人情報とファイル管理

出力ブックには氏名、ID、資格、受講希望等の個人情報・業務情報が含まれ得る。

- Git、issue、Pull Request、CI artifactへ追加しない。
- テストfixtureには実データを使わず、一時ディレクトリと架空名を使う。
- エラーログへ行全体や氏名を不要に出力しない。
- メール、クラウドストレージ等へ送る場合は、利用組織の個人情報取扱いに従う。
- `.gitignore`対象であっても、Git以外からの漏えいを自動的に防ぐものではない。

## 11. 架空データ入りの作成例

開発・操作練習用として、架空生徒50名、架空講師20名、既定23科目、講師対応科目、
受講希望を含むブックを生成できる。通常担当と第1～第3希望には、その科目を
「指導可能」とした講師だけを設定する。

```powershell
.\.venv\Scripts\python.exe tools\generate_master_data_example.py
```

既定の出力先:

```text
generated_examples\master_data_example_50_students_20_teachers.xlsx
```

出力先を変える場合:

```powershell
.\.venv\Scripts\python.exe tools\generate_master_data_example.py `
  --output "C:\任意の保存先\master_data_example.xlsx"
```

生成される氏名とIDはすべて架空である。生成した`.xlsx`は個人情報を誤ってGitへ
追加する事故を避けるため、他のExcel入出力と同様に`.gitignore`対象とする。
