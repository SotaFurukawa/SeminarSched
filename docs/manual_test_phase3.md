# Phase 3 手動確認手順

この手順は、Windows上でPhase 2までの機能を回帰確認しながら、Phase 3の日時希望
取込み、列マッピング、差分、集団授業、プロジェクト入力検証を確認するためのもので
ある。仕様上の基準は[公開仕様](specification.md)である。

実在する生徒、講師、校舎、アンケート回答は使用しない。この手順に記載した人物名は
すべて架空である。確認用の`.jukuschedule`、xlsx、CSVにも個人情報を入れない。

Phase 4のOR-Tools最適化、時間割の自動配置、未配置理由の生成は確認対象ではない。
入力検証画面の成功表示は、Phase 3でDBに表現できる入力範囲にエラーがないという
意味であり、Assignment依存の検証や最適化が実行されたという意味ではない。

## 1. 前提と隔離した確認領域

[README.md](../README.md)の開発環境構築手順に従い、Python 3.12の仮想環境と開発
依存関係を準備する。普段使用しているアプリ管理DBやログへ触れないよう、同じ
PowerShellプロセス内だけ保存先を一時ディレクトリへ変更する。

```powershell
$phase3Root = Join-Path ([System.IO.Path]::GetTempPath()) ("SummerSchedulerPhase3-" + [guid]::NewGuid().ToString("N"))
$inputRoot = Join-Path $phase3Root "日本語 入出力確認"
New-Item -ItemType Directory -Path $inputRoot

$env:SUMMER_SCHEDULER_DATA_DIR = Join-Path $phase3Root "data"
$env:SUMMER_SCHEDULER_LOG_DIR = Join-Path $phase3Root "logs"

$bootstrapProject = Join-Path $phase3Root "Phase3開始用_架空講習.jukuschedule"
$sampleProject = Join-Path $phase3Root "日本語 匿名サンプル.jukuschedule"
$deleteSampleProject = Join-Path $phase3Root "削除確認専用_匿名サンプル.jukuschedule"

$studentXlsx = Join-Path $inputRoot "生徒希望_手動確認.xlsx"
$teacherXlsx = Join-Path $inputRoot "講師希望_手動確認.xlsx"
$groupXlsx = Join-Path $inputRoot "集団授業_手動確認.xlsx"
$studentUtf8Csv = Join-Path $inputRoot "生徒回答_UTF-8_日本語.csv"
$teacherCp932Csv = Join-Path $inputRoot "講師回答_CP932_日本語.csv"

python -m summer_scheduler
```

PowerShellを閉じると、このプロセスに設定した環境変数は失われる。確認中は同じ
PowerShellからアプリを起動する。

## 2. Phase 2プロジェクトと匿名サンプルの生成

匿名サンプル作成ボタンはプロジェクトを開いているときに表示されるため、最初に開始用
プロジェクトを1件作る。

1. 「ホーム」→「新規プロジェクト」で次を入力し、`$bootstrapProject`へ保存する。

   | 項目 | 値 |
   |---|---|
   | プロジェクト名 | Phase3開始用 架空講習 |
   | 校舎名 | 架空確認校 |
   | 開始日 | 2026-08-03 |
   | 終了日 | 2026-08-07 |

2. サイドバーの「未配置・警告」を開く。
3. 「匿名サンプルを作成…」を押し、`$sampleProject`を指定する。
4. ヘッダーのプロジェクト名が「匿名サンプル 2026夏期講習」、校舎名が
   「架空みらい校」、期間が2026-08-03～2026-08-07へ切り替わることを確認する。
5. 次の架空データが作成されていることを画面で確認する。

   - 生徒10名以上。`S-001`～`S-010`で、氏名は「架空」で始まる
   - 講師5名以上。`T-001`～`T-005`で、氏名は「架空」で始まる
   - 複数科目と講師資格
   - 優先度5の受講希望
   - 1対1必須の受講希望
   - 最大連続3コマの例外
   - 生徒・講師の日時希望
   - 集団授業`GROUP-001`
   - 意図的な資格警告

6. アプリを終了して同じPowerShellから再起動し、日本語と空白を含む
   `$sampleProject`を最近使用したプロジェクトから開けること、上記データが保持される
   ことを確認する。

同じ操作で後述の削除確認専用ファイル`$deleteSampleProject`も生成してよい。ただし、
通常の確認と削除確認でファイルを取り違えないよう、ウィンドウタイトルを毎回確認する。

## 3. 3種類のテンプレート出力

日本語パスの`$inputRoot`へ次の3ファイルを出力する。

| 画面 | 操作 | 保存先 |
|---|---|---|
| アンケート取込み | 「生徒回答」→「生徒テンプレートを保存…」 | `$studentXlsx` |
| アンケート取込み | 「講師回答」→「講師テンプレートを保存…」 | `$teacherXlsx` |
| 集団授業 | 「group_lessons.xlsxを保存…」 | `$groupXlsx` |

Excelで開き、次を確認する。

| ファイル | 必須シート |
|---|---|
| 生徒希望 | `生徒希望`、`説明` |
| 講師希望 | `講師希望`、`説明` |
| 集団授業 | `集団授業`、`受講者`、`説明` |

各ファイルで、1行目が日本語ヘッダー、2行目が背景色と「例示行=はい」で区別された
架空例であることを確認する。例示行は取込み対象外である。Y/Z/A/B/C列には
0、1、2だけの入力規則があり、説明シートに「0=不可、1=可能、2=希望」が記載されて
いることも確認する。

テンプレートは既存ファイルへ直接書きかけの状態を残さず保存される。保存に失敗した
場合は日本語エラーが表示され、同じフォルダーへ壊れたxlsxが成功扱いで残らないことを
確認する。

## 4. 再現用ファイルの準備

### 4.1 生徒xlsx

`$studentXlsx`の`生徒希望`シート3行目へ次を入力する。2行目の例示行は変更しない。

| 例示行 | 生徒ID | 生徒名 | 科目コード | 日付 | Y | Z | A | B | C | 第1希望講師ID | 第2希望講師ID | 第3希望講師ID | 備考 |
|---|---|---|---|---|---:|---:|---:|---:|---:|---|---|---|---|
| いいえ | S-001 | 架空 青空 | JH_ENG | 2026-08-03 | 0 | 1 | 2 | 1 | 0 | T-001 |  |  | xlsx手動確認 |

`生徒希望`シートをコピーして`別回答`という名前にし、同じヘッダーと3行目を持たせる。
これにより、xlsxの複数シート選択を確認できる。

### 4.2 講師xlsx

`$teacherXlsx`の`講師希望`シート3行目へ次を入力する。

| 例示行 | 講師ID | 講師名 | 日付 | Y | Z | A | B | C | 備考 |
|---|---|---|---|---:|---:|---:|---:|---:|---|
| いいえ | T-001 | 架空 講師あおい | 2026-08-03 | 0 | 1 | 2 | 1 | 0 | xlsx手動確認 |

### 4.3 UTF-8 BOM付き生徒CSVとCP932講師CSV

列マッピングを目視確認できるよう、テンプレートとは異なる列名で2ファイルを作る。
次を、手順1と同じPowerShellで実行する。

```powershell
$studentCsvText = @'
回答者ID,表示氏名,講座科目,回答日,Y回答,Z回答,A回答,B回答,C回答,希望1,希望2,希望3,コメント
S-003,架空 星河,JH_ENG,2026-08-04,2,1,0,1,2,T-003,,,UTF-8手動確認
'@
$utf8Bom = [System.Text.UTF8Encoding]::new($true)
[System.IO.File]::WriteAllText($studentUtf8Csv, $studentCsvText, $utf8Bom)

$teacherCsvText = @'
職員番号,表示名,勤務日,Y可否,Z可否,A可否,B可否,C可否,コメント
T-003,架空 講師ひかり,2026-08-04,1,2,1,0,2,CP932手動確認
'@
$cp932 = [System.Text.Encoding]::GetEncoding(932)
[System.IO.File]::WriteAllText($teacherCp932Csv, $teacherCsvText, $cp932)
```

作成後、ファイルが`$inputRoot`配下にあり、リポジトリ直下へ生成されていないことを
確認する。

## 5. 生徒xlsx取込み

「アンケート取込み」で「生徒回答」を選び、次の順に確認する。

1. CSV文字コードは「CSV: 自動判定」のまま「回答ファイルを選択…」を押し、
   `$studentXlsx`を選ぶ。
2. ファイルパスに日本語ファイル名が文字化けせず表示されることを確認する。
3. シート一覧に少なくとも`生徒希望`、`別回答`、`説明`が表示されることを確認する。
4. `生徒希望`を選ぶ。`説明`を選んで検証した場合は必須列不足になり、DBへ反映
   できないことも確認してから`生徒希望`へ戻す。
5. 列マッピングに、生徒ID、生徒名、科目コード、日付、各コマ、希望講師、備考が
   表示され、同名列が自動対応していることを確認する。必須項目には`*`が表示される。
6. 「先頭行プレビュー」に例示行と入力行の元セル値が表示されることを確認する。
7. 「検証して差分を作成」を押す。
8. 例示行が取込み件数へ含まれず、3行目の5コマが追加、変更、または変更なしとして
   表示されることを確認する。
9. 差分に対象名、日付、コマ、変更前、変更後が表示されることを確認する。
10. エラーが0件なら「検証済み差分を反映…」が有効になることを確認する。
11. 「削除候補も反映」はチェックせず反映し、確認ダイアログに削除候補を保持する旨が
    表示されることを確認する。
12. 同じファイルを再度検証し、反映済みセルが「変更なし」になることを確認する。

希望講師`T-001`は`JH_ENG`を指導可能である。通常担当講師、優先度5、1対1契約は
アンケートから変更できない管理情報であり、これらに相当する列を追加した場合は
検証エラーとなって反映ボタンが無効になり、DBが変更されないことを別コピーで確認する。

## 6. 講師xlsx取込み

「講師回答」へ切り替え、`$teacherXlsx`で次を確認する。

1. シート`講師希望`を選ぶ。
2. 講師ID、講師名、日付、Y/Z/A/B/C、備考が自動マッピングされる。
3. 先頭行プレビューに3行目が表示される。
4. 検証後、`T-001`、2026-08-03の5コマについて差分が表示される。
5. エラー0件でのみ反映可能になり、削除候補のチェックを外した反映では、ファイルに
   ない他の日付・他講師の既存希望が保持される。
6. 再検証すると対象セルが「変更なし」になる。

## 7. UTF-8／CP932 CSVと手動列マッピング

### 7.1 UTF-8生徒CSV

1. 「生徒回答」と「CSV: 自動判定」を選び、`$studentUtf8Csv`を開く。
2. 文字コード表示がUTF-8系となり、「架空 星河」が文字化けしないことを確認する。
3. CSVは1つの表として表示され、xlsxのような別シート切替を要求されないことを
   確認する。
4. 列マッピングで次を手動選択する。

   | 保存先項目 | CSV列 |
   |---|---|
   | 生徒ID | 回答者ID |
   | 生徒名 | 表示氏名 |
   | 科目コード | 講座科目 |
   | 日付 | 回答日 |
   | Y/Z/A/B/C | Y回答/Z回答/A回答/B回答/C回答 |
   | 第1希望講師ID | 希望1 |
   | 備考 | コメント |

5. マッピング後のプレビュー、検証位置、5コマの差分を確認し、削除候補を含めず反映
   する。
6. 取込みをクリアして同じファイルを開き直したとき、保存済みマッピングが現在の
   ヘッダーに適用されることを確認する。ヘッダーが存在しない場合に古いマッピングを
   無理に適用しないことも確認する。

### 7.2 CP932講師CSV

1. 「講師回答」と「CSV: CP932」を明示選択し、`$teacherCp932Csv`を開く。
2. 「架空 講師ひかり」と「CP932手動確認」が文字化けしないことを確認する。
3. 次を手動マッピングする。

   | 保存先項目 | CSV列 |
   |---|---|
   | 講師ID | 職員番号 |
   | 講師名 | 表示名 |
   | 日付 | 勤務日 |
   | Y/Z/A/B/C | Y可否/Z可否/A可否/B可否/C可否 |
   | 備考 | コメント |

4. プレビュー、検証、差分を確認し、削除候補を含めず反映する。
5. 別途「CSV: 自動判定」でもCP932と判定されることを確認する。誤ったUTF-8指定で
   読めない場合は日本語エラーとなり、文字化けした人物を新規登録・反映しない。

## 8. アンケート検証エラーと削除候補

入力ファイルのコピーを作り、1項目ずつ次を試す。各確認後は正常ファイルへ戻す。

- コマ値を`3`、`-1`、文字列、空欄にする
- 未登録の生徒IDまたは講師IDにする
- 正しいIDに別人の氏名を組み合わせる
- 生徒の科目コードを未登録コードにする
- LessonRequestがない生徒・科目の組合せにする
- 日付を不正形式、講習期間外、休校日にする
- 同じ人物・同じ日付の行を重複させる
- 希望講師を未登録ID、または対象科目を指導不可の講師にする
- 生徒ファイルへ通常担当、優先度5、1対1契約を変更する列を加える

エラー・警告一覧に重要度、シート、行、列、内容が表示されることを確認する。エラーが
1件でもある場合は「検証済み差分を反映…」が無効で、正常に見える別行も部分反映
されない。

日時希望の差分は、ファイルに存在しない既存セルを削除候補として表示する。この範囲は
現在のプロジェクト内の既存希望全体へ及び得る。

1. 通常の`$sampleProject`では「削除候補も反映」をチェックせず反映する。
2. 反映後に同じ一部ファイルを再検証し、ファイルにないセルが引き続き削除候補として
   残ることを確認する。
3. `$deleteSampleProject`を開き、同じ一部ファイルを検証する。
4. 削除候補件数を記録し、「削除候補も反映」を明示チェックする。
5. 確認ダイアログに削除件数と、削除を実行する旨が表示されることを確認して反映する。
6. 再検証またはプロジェクト全体検証で、対象外セルが削除された結果を確認する。

手順4～6は必ず削除確認専用の匿名サンプルで行う。実運用プロジェクトでは実施しない。

## 9. 集団授業2シート、任意時刻、境界接触

`$groupXlsx`の例示行は残し、3行目以降へ次を入力する。

`集団授業`シート:

| 例示行 | 集団授業ID | 学年 | 科目コード | コース名 | 日付 | 開始 | 終了 | 担当講師ID | 教室 | 備考 |
|---|---|---|---|---|---|---|---|---|---|---|
| いいえ | G-EDGE-1 | J1 | JH_ENG | 架空境界1 | 2026-08-04 | 16:00 | 17:00 | T-001 | 架空A | 任意時刻 |
| いいえ | G-EDGE-2 | J1 | JH_ENG | 架空境界2 | 2026-08-04 | 17:00 | 17:30 | T-001 | 架空A | 境界接触 |

`受講者`シート:

| 例示行 | 集団授業ID | 生徒ID |
|---|---|---|
| いいえ | G-EDGE-1 | S-001 |
| いいえ | G-EDGE-2 | S-002 |

確認手順:

1. 「集団授業」→「Excel取込み・差分」→「group_lessons.xlsxを選択…」で
   `$groupXlsx`を選ぶ。
2. 2つの必須シートを読み込み、「検証して差分を作成」を押す。
3. 16:00～17:00と17:00～17:30は境界が接するだけなので、同じ講師でも時間重複
   エラーにならないことを確認する。
4. Y/Z/A/B/Cと完全一致しない時刻でも受け付け、差分に`G-EDGE-1`と`G-EDGE-2`が
   追加として表示されることを確認する。
5. 既存`GROUP-001`はファイルにないため削除候補となるが、「削除候補も反映」は
   チェックせず反映する。
6. 「登録済み一覧」に`GROUP-001`、`G-EDGE-1`、`G-EDGE-2`が表示され、日付、任意
   時刻、講師、受講者数、教室が保持されることを確認する。

別コピーで`G-EDGE-2`の開始を`16:59`へ変更すると、同じ講師の時間区間が重なるため
検証エラーとなり反映できないことを確認する。さらに、次も1件ずつ確認する。

- 集団授業ID重複
- 開始時刻と終了時刻が同じ、または開始が終了より後
- 不正な日付・時刻、講習期間外、開校日外
- 未登録科目、講師、生徒
- 担当講師の科目資格違反
- 同一講師の集団授業時間重複
- 同一生徒の集団授業時間重複
- `受講者`から存在しない集団授業IDを参照

エラー0件の場合だけ反映ボタンが有効になることを確認する。集団授業の削除候補も、
削除確認専用の匿名サンプルでのみ明示チェックと確認ダイアログを通して反映する。

## 10. ValidationIssue分類と再検証

通常の`$sampleProject`を開き、「未配置・警告」で確認する。

1. 「プロジェクト全体を検証」を押す。
2. 上部に「エラー」「警告」「情報」が色だけでなく記号と文字でも表示されることを
   確認する。
3. 匿名サンプルに意図的に含まれる、希望講師`T-005`が対象英語科目を指導不可という
   警告を確認する。
4. 重要度フィルターと、メッセージ・検証種別・対象IDの部分検索を確認する。
5. 行ごとに検証種別、対象種別、対象ID、メッセージ、詳細が表示されることを確認する。
6. エラー0件なら「Phase 3で扱う入力範囲にエラーはありません」、エラーがあれば
   「エラーを解消するまで最適化を開始できません」と表示されることを確認する。

再検証による更新は次で確認できる。

1. 講師希望ファイルへ`T-002`の2026-08-03～2026-08-07を5行追加し、全コマを
   `0`にして検証・反映する。削除候補は含めない。
2. 「プロジェクト全体を検証」を再実行する。
3. 優先度5で`T-002`が必須の生徒について、共通可能枠不足がエラーになり、
   最適化を開始できない表示になることを確認する。
4. 同じ5行の全コマを`1`へ戻して再取込みし、再検証する。
5. 解消したエラーが現在の一覧から消え、件数が更新されることを確認する。以前の
   ValidationIssueはDB上で解決済みへ更新され、同じ未解決行として重複表示されない。
6. 意図的な資格警告は原因を修正しない限り警告として残ることを確認する。

プロジェクト全体検証では、少なくともマスター参照、日時希望不足、優先度5講師との
共通可能枠、講師資格、集団授業衝突、コマ時刻重複、休校日、有効でないマスター参照を
確認する。これは最適化前検証であり、Phase 4の解生成や未配置理由生成ではない。

Assignmentがまだ存在しないPhase 3では、「1対1必須の割当矛盾」「固定授業同士の
重複」「集団授業と固定授業の衝突」は発生させられない。これらを検査済みと偽って
扱わず、Phase 4でAssignmentを追加した時点で同じプロジェクト全体検証へ接続して
確認する。

## 11. transaction失敗時の観察可能範囲

GUIで安全に確認できる範囲は次のとおりである。

- プレビューと検証だけではDB一覧・件数が変わらない
- エラーを含む取込みは反映ボタンが無効で、正常行も部分反映されない
- 反映確認で「いいえ」を選ぶと何も保存されない
- 反映処理は成功メッセージと件数が出た場合だけ完了扱いにする
- 反映時に日本語エラーが出た場合、プロジェクトを閉じて再度開き、差分と一覧を確認し、
  追加・変更・削除が一部だけ残っていないことを確認する

DB書込み後、ImportBatch記録時だけ意図的に例外を発生させる操作は通常のGUIへ設けて
いない。ファイルロック、強制終了、DB破損を使って故障を作らない。transaction全体の
rollbackは次の自動テストで再現する。

```powershell
python -m pytest -q tests/integration/test_availability_import_service.py
python -m pytest -q tests/integration/test_group_lesson_service.py
python -m pytest -q tests/unit/test_phase3_repository.py
```

これらは可用性書込み後のImportBatch失敗、集団授業書込み後の失敗、Repositoryの
明示rollbackで、部分反映が残らないことを検証する。
