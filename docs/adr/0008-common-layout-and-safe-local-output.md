# ADR 0008: 共通帳票レイアウトと検証済み原子的ローカル出力を採用する

- 状態: 採用・Phase 6実装済み
- 日付: 2026-07-29
- 対象: 全体・生徒別・講師別・未配置／警告帳票、Excel、PDF、CSV、印刷プレビュー

## コンテキスト

Phase 6では、同じ時間割を編集可能なExcelと印刷用PDFへ出力し、生徒別、講師別、
未配置・警告一覧にも展開する必要がある。帳票ごと、形式ごとに業務データの解釈を
複製すると、ExcelとPDFで表示内容や改ページがずれ、最適化後にDBが変更された場合に
古い画面状態を出力する危険がある。

出力には氏名等の個人情報が含まれ得る。既存ファイルを生成途中で壊さず、同名ファイルを
確認なしに上書きせず、外部通信やクラウド変換を必要としないことも必須である。
QMLへSQLAlchemy Session、ハード制約、ファイル生成処理を持ち込んではならない。

業務上の参考PDFは個人情報を含む可能性があるため、公開リポジトリ、外部サービス、
実行時依存、テストfixtureのいずれにも使用しない。特定資料の直接比較や
ピクセル単位の再現を設計根拠にしない。

## 決定

### 1. ExcelとPDFの正本を不変な共通レイアウトにする

DBの読取り結果を`OutputSnapshot`へコピーし、純粋な帳票builderが次の不変型へ変換する。

- `LayoutDocument`: 帳票種別、タイトル、校舎、講習名、更新日時、用紙、向き、余白、
  文字サイズ、任意ロゴ
- `LayoutSection`: Excelのシートまたは帳票上のまとまり
- `LayoutPage`: 物理ページの見出し、表、フッター
- `LayoutTable` / `LayoutRow` / `LayoutCell`: 列幅、見出し、セル結合、文字、役割、
  表示ルール、配置

```text
SQLite / SQLAlchemy
  → OutputRepository
  → OutputSnapshot
  → 帳票builder
  → LayoutDocument
      ├─ ExcelRenderer
      └─ HtmlRenderer → QtPdfRenderer
```

全体、生徒別、講師別、未配置・警告のbuilderは`reporting/`へ置く。ExcelとPDFで
別々にAssignmentや未配置理由を解釈しない。日付、講師、生徒の選択もbuilderへ渡す
`OutputSelection`で表現し、QMLの表示状態を帳票ロジックへ漏らさない。

全体時間割は日付数と講師列数で物理ページへ先に分割する。生徒別は1人1ページまたは
2人ずつまとめる方式、講師別は講師と日付範囲、未配置・警告は行数で分割する。
色だけで状態を表さず、1対1、集団、ロック、警告、未確定、手動変更、休校の文字
マーカーを常に併用する。

### 2. 編集可能なExcelにはopenpyxlを使う

`ExcelRenderer`は共通レイアウトを`openpyxl`のWorkbookへ変換する。Windowsに
Excelがインストールされていない環境でも生成でき、Excel COM自動化や外部サービスを
必要としない。

レンダラーは次を設定する。

- A3 / A4、縦横、余白、横方向1ページへのfit
- 罫線、セル結合、列幅、行高、文字折返し、縮小表示
- 印刷範囲、物理ページ境界の手動改ページ、見出し行、ヘッダー／フッター、ページ番号
- 背景色と文字マーカー、明示的な文字列型

利用者入力が`=`等で始まっても数式に変換せず、文字列として保存する。Excelは
`LayoutDocument`のロゴパスを現時点では画像として埋め込まない。ロゴはPDFの
印刷ヘッダーで利用する。

### 3. PDFはQtのローカル描画とし、同じ一時PDFをプレビューする

`HtmlRenderer`は各`LayoutPage`を、Qt rich textで解釈可能なtable中心のHTMLへ変換する。
利用者文字列はHTML escapeし、ロゴは対応するローカル画像を5MB以下に制限して
data URLへ埋め込む。ネットワークへ画像や帳票データを送信しない。

`QtPdfRenderer`は`QTextDocument`と`QPdfWriter`でA3 / A4 PDFを生成する。Windowsの
日本語標準フォントを優先して選び、フォントファイルは同梱しない。ページ内容が収まらない
場合は縮小するが、倍率が0.62未満になる場合は読めないPDFを作らず、日数または講師列数を
減らすよう明示エラーにする。

生成後は`QPdfDocument`で一時PDFを再読込みし、ファイルサイズ、ページ数、各ページ寸法を
検証する。QMLの印刷プレビューは、保存用と同じ経路で作った一時PDFを
`QtQuick.Pdf`の`PdfDocument` / `PdfMultiPageView`へ渡す。ページ送り、50～300%の
拡大縮小、幅合わせ、全体表示を提供する。一時PDFは切替時とアプリ終了時に削除する。

Chromiumを同梱しないことで配布サイズと別runtime依存を抑える。一方、
`QTextDocument`が対応するHTML / CSSの範囲にレイアウトを限定し、ブラウザー固有CSSへ
依存しない。

### 4. 実ファイル出力の直前に現在DBを独立検証する

実際のExcel、PDF、CSV出力では、画面読込み時のcacheを使用せず、毎回現在DBを
再読込みする。`OutputService`は次の順で処理する。

1. `ProjectValidationService`で保存済み入力と警告を更新する。
2. 短いSQLAlchemy Session内で`OutputSnapshot`と最適化入力を構築する。
3. 現在の全Assignmentと未配置sessionから完全な`OptimizationResult`を再構築する。
4. Phase 4のsolverから独立した`validate_optimization_result()`を実行する。
5. ハード制約違反、session partition不整合、参照欠落があれば出力を中止する。
6. 検証済みsnapshotだけを帳票builderとrendererへ渡す。

これにより、出力は不正な時間割を「見た目だけ正常」に帳票化する経路にならない。
画面を開いた後にAssignmentが変更されても、実出力は最新状態を使う。

未配置の「単独配置可」候補は、現在の結果へ対象sessionを1件だけ仮追加し、同じ独立
validatorを通過した最大3件に限定する。これは現在の他Assignmentを動かさず1件追加する
場合の実行可能性であり、複数候補の同時適用や最適性を保証するものではない。該当候補が
ない場合は、診断コードに対応する条件確認案を表示する。

### 5. すべての保存を同一ディレクトリの一時ファイル経由にする

Excel、PDF、CSVは最終保存先と同じディレクトリに一時ファイルを作り、生成処理
（PDFでは生成後の再読込み検証を含む）が成功した後だけ`os.replace`で最終名へ
置き換える。既存の最終ファイルを先に削除しない。

- `overwrite=False`では既存ファイルを拒否し、QMLから明示確認を要求する。
- 一時ファイル作成後にも同名ファイルのraceを再確認する。
- 権限不足、Excel等によるロック、書込み失敗を日本語の型付き例外に変換する。
- 失敗時は一時ファイルを削除し、既存ファイルを保持する。

### 6. 既定値とプロジェクト設定を分けて保存する

配布時の既定値は`default_settings.yaml`、利用者による既定値の上書きは
`config.yaml`から`OutputSettingsDefaults`へ読み込む。プロジェクトで初めて保存した後は、
Alembic revision `20260729_0006`の`output_settings`を正本とする。

`output_settings`はプロジェクトと1対1で、用紙、向き、表示項目、日数、講師列数、
文字サイズ、余白、ファイル名規則、既定出力先、生徒別改ページ、CSV BOM、色と
マーカーを保持する。ロゴは二重管理せず`Campus.logo_path_optional`を正本とする。
範囲、Windowsファイル名、色形式、必須マーカーはPythonとDB制約で検証する。

QMLはdraft設定と選択IDだけを`OutputViewModel`へ渡す。設定保存、DB読取り、検証、
帳票生成はApplication Service以下で行い、重い出力は`QThread` workerで実行する。

## 根拠

- 共通レイアウトを正本にすると、ExcelとPDFで情報構造、ページ分割、状態表示を共有できる。
- openpyxlとQtはいずれもローカルで完結し、Office COM、ブラウザー、クラウド変換を
  実行時依存にしない。
- 保存用と同じPDFをプレビューすると、「プレビューだけ別レイアウト」になる差を減らせる。
- 独立validatorと最新DB再読込みにより、solver、QML、古いcacheを信頼せず出力を止められる。
- 同一ディレクトリの一時ファイルと`os.replace`により、部分生成物や壊れた上書きを
  最終成果物として残しにくい。

## 影響

良い影響:

- QMLなし、DBなしで帳票builderとレイアウトを単体テストできる。
- 同じ`LayoutDocument`をExcelとPDFの双方で回帰確認できる。
- 日本語パス、複数ページ、長い氏名、2名枠、1対1、集団、休校、警告を匿名fixtureで
  検査できる。
- CSVはPython標準`csv`で18列を固定し、BOM有無を選択できる。表計算ソフトの
  数式注入候補文字も文字列として保護する。

注意点:

- 期待される参考PDFが不在のため、参考資料との視覚的近似は直接検証していない。
- PDFの結果はWindowsに存在する日本語フォントとQtのrich text描画に依存するため、
  Windows実機、DPI、プリンタードライバーで手動確認する。
- Qt rich textは完全なブラウザーCSSではない。情報密度が高すぎる設定は自動で
  極小文字にせず明示エラーになる。
- ロゴはPDFヘッダーへ埋め込むが、Excelには現時点で画像を埋め込まない。
- プレビューはPDFだけで、CSV生データには提供しない。
- 出力workerはファイルを半端な状態で強制停止しない。終了時に30秒を超えると警告後も
  完了を待つため、OSや外部ファイルシステムが応答しない場合はアプリ終了が遅れ得る。
- 出力ファイル、一時プレビュー、プロジェクトDBには個人情報が含まれ得る。Git、CI
  artifact、issue、チャット、外部サービスへ送らない。

## 採用しなかった案

- ExcelとPDFで別々の業務データbuilderを作る: 表示内容と未配置理由が分岐するため
  採用しない。
- QML JavaScriptでDBを読み、表やCSVを生成する: レイヤー分離、独立検証、GUIなし
  テストを損なうため採用しない。
- Excel COM自動化: Excelのインストール、Windows固有process、対話dialogに依存するため
  採用しない。
- Chromiumを必須同梱する: 現段階ではQtだけで必要なtable出力とプレビューを実現でき、
  配布サイズと更新対象が増えるため採用しない。
- 最終ファイルへ直接書き込む: 失敗時に部分ファイルや破損した既存ファイルを残し得るため
  採用しない。
- 画面cacheをそのまま出力する: 表示後のDB変更や手動編集を取りこぼすため採用しない。
- validator違反を警告だけ表示して出力する: ハード制約違反を正しい時間割として配布し得る
  ため採用しない。

## 検証方針

自動テストでは次を確認する。

- 共通レイアウトの情報、ページ分割、選択filter、表示項目、色と文字マーカー
- Excelの再読込み、主要セル、文字列型、罫線、結合、折返し、印刷設定、改ページ
- Qt offscreen PDFの日本語パス、A3横、ページ数、寸法、上書き拒否
- PDF / Excel / CSVの原子的保存、上書き、失敗時の既存ファイル保持
- CSVの18列、BOM有無、集団授業、選択filter、数式注入候補の保護
- 生徒別、講師別、未配置・警告、長い架空名、2名枠、1対1、集団、休校、大人数
- 最新DBの再読込み、独立validator違反時の全出力拒否、単独配置可候補の再検証
- `20260729_0005 → 20260729_0006`のupgrade / downgrade、設定全項目のround trip

Windows実機のPDF表示、ページ送り、拡大縮小、Excel / PDF / CSV、権限・ロック、
日本語パス、ロゴ、選択、設定再読込み、個人情報の取扱いは
[`manual_test_phase6.md`](../manual_test_phase6.md)で確認する。
