# 未署名配布・完全性確認方針

Status: **社内利用向け成果物は意図的に未署名で配布します。**

SignPath Foundationへの申請は公開実績の要件を満たさず承認されませんでした。プロジェクト
所有者と利用組織は、当面コード署名を使用せず、許可された社内PCだけへ配布する方針を
選択しました。SignPath、有料証明書、自己署名証明書をリリース工程で使用しません。

## リリース成果物

- Windows実行ファイル、ポータブルZIP、Inno Setupインストーラーは未署名です。
- GitHub Actionsは、自作EXEとインストーラーが署名されていないことを
  `scripts/verify_authenticode.ps1 -RequireUnsigned`で確認します。
- 意図しない署名が見つかった場合、リリース処理を失敗させます。
- リリースノートには「未署名」と明記し、「署名済み」「認証済み発行元」と表記しません。

## ダウンロード後の確認

GitHub Releaseに添付された`SHA256SUMS.txt`とダウンロードしたファイルのSHA-256を
照合します。PowerShellでは次のように確認できます。

```powershell
Get-FileHash .\SummerCourseScheduler-Setup-1.3.0.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

SHA-256は破損や取り違えの検出に使用できますが、発行者を証明するコード署名の代替では
ありません。Releaseページのリポジトリ所有者、タグ、Actionsの成功、ファイル名も確認
してください。

## Windowsの警告

未署名成果物では、Windows SmartScreenや組織のセキュリティ製品が「不明な発行元」等の
警告を表示したり、実行を禁止したりする場合があります。Windowsの保護機能を恒久的に
無効化しないでください。利用組織の管理者が配布元とSHA-256を確認し、組織の手順で
実行を許可した場合だけ使用します。

将来署名を再検討する場合は、組織の承認、費用負担、証明書管理、CIの秘密情報管理を
含む新しい設計判断とレビューを行います。現在のリリース手順へ署名工程を追加する予定は
ありません。
