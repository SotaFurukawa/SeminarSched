# 季節講習時間割作成アプリ 利用者マニュアル

## 基本の6ステップ

ホームに表示される次の順で操作します。

1. ホームの共通名簿を確認し、「授業日を設定」で講習期間、開校日、コマを確定する。
2. 「アンケート作成」で、設定日時を反映した生徒用・講師用フォーム作成キットを出力する。
3. 回答後、「回答取込み」で生徒・講師回答を検証・反映する。
4. 保護者等と調整済みの個別枠があれば、「事前確定」で生徒・講師・日付・コマを固定する。
5. 「時間割」で自動配置と手動確認を行う。
6. 「出力」で全体時間割に加え、生徒ごとのExcel・PDFを作成する。

新規プロジェクトは年度と春期／夏期／冬期を選ぶと、`2026夏期講習`のような名前が
自動設定されます。保存先と校舎名は入力不要です。アプリが利用者別の安全な保存領域に
`生徒`、`講師`、`プロジェクト`フォルダを作り、プロジェクトを自動保存します。「既存
プロジェクトを開く」は最初からこのフォルダを表示し、最近使用したファイルはホームから
直接開けます。

ホームの「生徒・講師の基本情報（共通）」には、「新規で基本情報を作成」、
「作成した基本情報を反映」、「反映済みの基本情報を開いて編集」の3操作があります。
反映済みExcelは`生徒・講師_基本情報.xlsx`です。
在籍情報、指導可能科目、通常授業の担当はこの1ファイルを正本とし、新規講習へ自動反映
します。新しいブックを取り込むと、検証後に共通正本をバックアップし、開いている講習へ
同時に反映します。反映済みExcelを直接編集した場合は、保存後にもう一度同じファイルを
「作成した基本情報を反映」で選択します。
過去講習は開いただけでは最新名簿へ変更されません。

Excelの在籍は生徒・講師ともA列のセル内チェックボックスをワンクリックして切り替えます。
各行に「在籍」「退籍」の文字を入力する必要はありません。チェックを外した人は削除されず、
入力済み行の末尾へ移動して行全体が灰色になります。姓を入力すると自動でチェックが付き、ID候補と
既定値が数式で表示されます。生徒は最大連続`2`・空きコマ`なし`、講師は空きコマ`なし`が
既定です。アプリへ反映すると未使用の`S-0001`／`T-0001`形式へ正式採番して書き戻します。
薄い黄色のセルは入力必須です。
セル内チェックボックスにはMicrosoft 365またはExcel 2024以降を使用してください。古い
Excelでは`TRUE`／`FALSE`と表示されますが、アプリは同じ在籍値として読み込めます。
必要授業回数と日時アンケートは講習ごとに異なるため、共通名簿には保存しません。

アンケートを反映すると、選択したxlsx/CSVの内容が`.jukuschedule`内へ保存されます。
元ファイルを再度選ぶ必要はありません。新しい回答を反映すると、保管中の同種原本は新しい
内容へ差し替わります。取込み履歴と監査履歴は残ります。

生徒画面の「在籍中」を外すと卒業・退会扱いとなり、一覧の末尾へ移動して灰色表示されます。
講師も同様に、在籍中を外すと退職・休止として末尾へ表示されます。

対象: `1.6.0 (Beta)`
最終更新: 2026-09-05

初めて利用する場合は、先に
[はじめて使う人のための簡単操作ガイド](quick_start_guide.md)を参照してください。
Googleフォームの具体的な質問項目と回答変換手順は
[Googleフォーム アンケート作成・取込みガイド](google_forms_questionnaire_guide.md)
にまとめています。

アンケートテンプレートには、生徒・講師・科目の参照シートが同じブック内に
出力されます。回答入力時はIDを一覧から選択し、対応する名前・科目名を確認できます。
参照シートは確認用であり、マスター情報の更新は設定画面の`master_data.xlsx`取込みで
行います。

## 1. はじめに

このアプリは、夏期・冬期・春期講習などの不定期講習について、個別指導の希望、
講師の出勤、講師の指導可能科目、1対1契約等を照合し、時間割を作成・編集・
出力するWindows向けローカルアプリです。

- データは選択したPC内の`.jukuschedule`へ保存されます。
- クラウドDB、テレメトリ、Google APIの直接連携を使用しません。
- Googleフォームの回答は、回答画面と直接接続せず、xlsxまたはCSVにして取り込みます。
- 条件を満たせない授業は、無理に配置せず「未配置」として理由を表示します。

`.jukuschedule`、入力Excel / CSV、出力Excel / PDF / CSV、backup、logには個人情報が
含まれる可能性があります。外部共有、メール添付、USBの紛失、印刷物の置き忘れに
注意してください。

## 2. 対応環境と入手

対象環境はWindows 10 / 11 x64です。

本番GitHub Releaseはまだ公開されていません。公開後は公式Releaseページから次を
入手します。

```text
SummerCourseScheduler-Setup-<version>.exe
SummerCourseScheduler-Portable-<version>.zip
SHA256SUMS.txt
```

Releaseページ以外から受け取った実行ファイルを安易に実行しないでください。
公開版では`SHA256SUMS.txt`とダウンロードしたファイルのSHA-256を照合します。

```powershell
Get-FileHash .\SummerCourseScheduler-Portable-1.6.0.zip -Algorithm SHA256
Get-FileHash .\SummerCourseScheduler-Setup-1.6.0.exe -Algorithm SHA256
```

表示されたhashがReleaseページの値と1文字でも異なる場合は使用しません。

### 2.1 インストーラー版

1. installerを公式Releaseからdownloadします。
2. SHA-256を確認します。
3. installerを起動し、install先とshortcutを確認します。
4. desktop shortcutは任意です。不要なら選択を外します。
5. install後、Start menuから「季節講習時間割作成アプリ」を起動します。

初期の署名なし候補ではSmartScreenに「認識されないアプリ」と表示される可能性が
あります。公式Release URLとSHA-256を再確認しても組織のpolicyで許可されない場合は、
管理者へ相談してください。SmartScreenやantivirusを恒久的に無効化しないでください。

uninstallしても、利用者が作成した`.jukuschedule`、backup、config、logを勝手に
削除しない方針です。uninstall前には必要なprojectを別媒体にもbackupしてください。

### 2.2 portable版

1. ZIPを公式Releaseからdownloadし、SHA-256を確認します。
2. ZIPを右クリックして「すべて展開」します。
3. ZIP内から直接起動せず、展開したfolder内の実行ファイルを起動します。
4. app folderを移動しても、利用者dataは既定では`%LOCALAPPDATA%\SummerScheduler`へ
   保存されます。app本体のfolderと個人dataの保存先は別です。

portable版も利用者側のPython、Node.js、開発環境を必要としない構成を目標とします。
USB等で移動する場合、`.jukuschedule`はアプリとは別に安全に管理してください。

## 3. 初回起動と画面

初回起動時、利用者別のlocal領域へapp管理DBとlogを作ります。

| 種類 | 既定場所 |
|---|---|
| app管理DB | `%LOCALAPPDATA%\SummerScheduler\data\summer_scheduler.db` |
| log | `%LOCALAPPDATA%\SummerScheduler\logs\summer_scheduler.log` |
| 自動・migration前・復元前backup | `%LOCALAPPDATA%\SummerScheduler\backups\` |
| 任意の利用者設定 | `%LOCALAPPDATA%\SummerScheduler\config.yaml` |

app管理DBは最近使ったproject等を保持し、生徒・講師・授業は保持しません。業務dataは
アプリが管理するプロジェクトフォルダー内の`.jukuschedule`に入ります。「名前を付けて
保存」を使った場合だけ、利用者が選んだ場所へ別名保存されます。

左のsidebarは、ホーム、生徒・講師の基本情報、次の6段階の業務フロー、確認に分かれています。

1. ①設定
2. ②アンケート作成
3. ③アンケート取込み
4. ④事前確定
5. ⑤時間割
6. ⑥出力

生徒・講師の基本情報はホーム直下、未配置・警告は「確認」から開けます。

画面左下のversion表示からAboutを開くと、app versionと対応DB schema revisionを
別々に確認できます。問い合わせ時は両方を記録してください。

## 4. 新しいprojectを作る

1. 「ホーム」を開きます。
2. 「新規project」を選びます。
3. 年度と「春期／夏期／冬期」をプルダウンで選びます。
4. 講習開始日・終了日を2020～2070年の年・月・日プルダウンで選び、作成します。project名は、例えば
   `2026夏期講習`のように自動設定されます。

保存先と内部校舎名はアプリが自動管理するため、新規作成時の指定は不要です。

作成直後は次が初期登録されます。

- Y 14:10–15:30
- Z 15:40–17:00
- A 17:10–18:30
- B 18:40–20:00
- C 20:10–21:30
- 講習期間内の日付
- 小学校7科目、中学校5科目、高校14科目

保存先に既存fileがある場合、確認なしに上書きしません。OneDrive同期folderでも
使用できますが、同期中のSQLite競合を避けるため、作業中projectはlocal folderに置き、
appのbackup機能で同期先へ複製する運用を推奨します。

## 5. project・コマ・開校日

「設定」からproject情報、コマ、開校日、科目を編集します。

### 5.1 project情報

- 年度
- 講習区分（春期／夏期／冬期）
- 自動設定されるproject名
- 講習開始日・終了日（2020～2070年の年・月・日プルダウン）

期間を変更する場合、既存の開校日、availability、Assignmentが範囲外に
ならないか確認します。入力検証のerrorを残したまま最適化は開始できません。

### 5.2 コマ

コマcode、表示名、開始・終了、順序、使用可否を設定します。

- 開始時刻は終了時刻より前にします。
- 有効なコマ同士を重ねません。
- codeと順序を重複させません。
- 連続授業と空きコマは時刻ではなく順序で判定します。

使用済みコマを削除・無効化すると既存dataへ影響します。警告内容を読んでから操作します。

### 5.3 開校日

各日付カード右上のチェックボックスで複数日を選び、「選択日を休校」または
「選択日を開校」を押すとまとめて変更できます。開校日ごとに使用するコマを選ぶと、
カレンダーの表示もその場で更新されます。別の日を選んでも未保存の編集内容は保持されます。
すべての日付を編集し終えたら「すべての変更を保存」を1回押して反映します。
「変更を破棄」では最後に保存した状態へ戻せます。

## 6. 科目

「設定」→「科目」でcode、表示名、学校段階、順序、使用中／停止を設定します。

小学校の算数・国語は中学受験と中学受験以外を分け、高校数学は数学IA・数学IIBC・
数学IIIを分けて管理します。一方を指導可能にしても他方へ自動判定されません。
講師画面で各科目を明示的に設定してください。

既存LessonRequestで使う科目は削除せず、通常は「使用停止」にします。

## 7. 生徒とLessonRequest

「生徒」では一覧の検索、追加、編集、使用停止、削除を行います。

### 7.1 生徒の基本情報

- 生徒ID: 保存時に`S-0001`形式で自動採番される安定したID（入力不要）
- 氏名
- 学年
- 標準の最大連続コマ数（既定2）
- 空きコマを許可するか（既定は許可しない）
- 備考
- 使用中／停止

内部では名前だけで生徒を識別せず、同姓同名でも区別できる自動IDを使います。
Excelでは小学を`S`、中学を`J`、高校を`H`で表し、例えば高2は`H2`と入力します。
画面とGoogleフォームは従来どおり「高2」等で表示されます。

### 7.2 科目別の受講希望

生徒ごと、科目ごとにLessonRequestを登録します。

- 必要回数
- 通常担当講師
- 通常担当優先度1～5
- 第1～第3希望講師
- 1対1必須
- 最大連続数の上書き
- 空きコマ許可の上書き
- 備考

優先度5は「通常担当講師が必須」です。その講師で条件を満たせない場合、他講師へ
自動変更せず未配置になります。優先度5なのに通常担当がない場合はerrorです。

「1対1必須」の授業がある講師・日時へ、別生徒を同時に配置しません。

## 8. 講師と指導可能科目

「講師」では次を設定します。

- 講師ID（保存時に`T-0001`形式で自動採番・入力不要）
- 氏名
- 空きコマを許可するか
- 備考
- 使用中／停止
- 各科目を指導できるか

同じ講師・同じ日・同じコマは最大2名です。異なる学年・科目の2名でも、講師が両科目を
指導可能なら同時指導候補になります。1対1必須が1名でも含まれる場合は2名にしません。

## 9. マスターExcel

新規導入時の共通名簿は、ホームの「生徒・講師の基本情報（共通）」から
「新規で基本情報を作成…」を選び、`生徒・講師_基本情報.xlsx`を編集してから
「作成した基本情報を反映…」で反映します。数十人を1人ずつ登録する必要はありません。
反映後は、大きな青い「反映済みの基本情報を開いて編集」から同じ正本を開けます。設定画面にはExcel入出力を
置きません。

sheetは次の5枚です。

- 生徒
- 講師
- 科目
- 講師対応科目
- 通常授業

1行目の日本語headerとsheet名を変更しません。2行目以降は、必要な入力欄、プルダウン、
自動参照式、既定値を備えた入力行です。

「講師対応科目」と「通常授業」では、「名前から選択」のプルダウンを使います。選択すると
隣の講師ID・生徒ID・科目コードへ数式で自動表示されます。「（確認）」だけの重複列は
新しいテンプレートにはありません。科目も名前から選択できます。登録済み行は安定IDを
参照して氏名・科目名を表示するため、生徒・講師・科目シートの名称を変更すると通常授業と
講師対応科目の表示も自動更新されます。既存行の相手を変える場合は、同じ名前選択セルで
別の候補を選び、アプリへ取り込むと新しいIDへ更新されます。
同姓同名の場合だけは、自動採番後のIDを確認して対象を選んでください。
生徒の最大連続コマ数、空きコマ許可、有効を空欄にすると、それぞれ`2`、`いいえ`、
`はい`として取り込みます。

取込みは、fileを選んだだけではDBを変更しません。

1. fileを読む。
2. 行番号・列名付きで検証する。
3. 新規／更新件数とerror / warningをpreviewする。
4. errorがないことを確認する。
5. 利用者が反映を選んだときだけ5sheetを1transactionで保存する。

途中で失敗した場合、一部のsheetだけを保存しません。

## 10. アンケートを作成・取り込む

### 10.1 Googleフォーム作成キットを出力する

①で開校日とコマを設定してから、②「アンケート作成」を開きます。画面に表示される
開校日数と有効コマ数を確認し、生徒用・講師勤務日時用のフォーム名、
回答締切を年・月・日のプルダウンで選び、問い合わせ先を入力します。

初めて作成する場合は「作成手順」を選ぶと、次の10段階を実際の画面と同じ
場所で確認できます。この案内はオフラインで表示され、Google側の画面が更新された場合は
ボタン名や配置が多少異なることがあります。手順画面の左下にある
「別ウィンドウで表示」を押すと、アプリの操作画面と並べて確認できます。

1. 「フォーム作成キットを保存…」からキットを保存します。
2. 「保存先を開く」で出力フォルダーを開きます。
3. `create_student_questionnaire.gs`をメモ帳で開き、全内容をコピーします。
4. `https://script.google.com/home`から新しいプロジェクトを作り、初期コードを削除します。
5. メモ帳からコピーした内容を`Code.gs`へ貼り付けます。
6. Ctrl+Sまたは保存ボタンで保存し、`createStudentQuestionnaire`を選んで実行します。
7. 初回の「承認が必要です」で「権限を確認」を押します。
8. Googleの警告では「詳細」を表示し、自分で保存したコードであることを確認してから
   「無題のプロジェクト（安全ではないページ）に移動」を押します。
9. 「すべて選択」にチェックを入れ、権限内容を確認して「続行」を押します。
10. 実行ログの回答URLからフォームを開きます。フォーム編集URLと回答原本URLは担当者だけで
    管理します。Apps Scriptの「デプロイ」は不要です。

講師勤務日時用と講師指導可能科目用も別々のApps Scriptプロジェクトで同じ手順を行い、
それぞれ`createTeacherQuestionnaire`と`createTeacherSubjectQuestionnaire`を実行します。

出力には、現在のプロジェクトで開校にした日、有効な時間帯、有効な科目が反映されます。
変更が必要な場合は①へ戻って設定し直し、新しいキットを出力してください。アプリはGoogleへ
直接接続せず、回答、氏名、メールアドレス等の個人情報をスクリプトへ書き出しません。
Googleフォームの共有範囲と回答原本の閲覧者は、組織の運用ルールに従って設定してください。
指導可能科目用フォームは講師のメールアドレスを収集しません。回答は自動反映せず、内容を
確認してから共通の`生徒・講師_基本情報.xlsx`へ反映してください。

### 10.2 生徒・講師回答を③でまとめて取り込む（推奨）

1. Google回答表で「ファイル」→「ダウンロード」→「カンマ区切り形式（.csv）」を
   選び、生徒用・講師用をそれぞれ保存します。
2. 「生徒・講師回答をまとめて取り込む」の左右へ各ファイルを選択します。
3. 「2ファイルを検証」を押します。
4. 赤い行があれば、共通名簿またはフォーム回答を修正して再検証します。未登録の生徒が
   体験生の場合は、赤い行の選択欄を「体験生として登録」へ変更します。黄色へ変わり、
   共通名簿を変更せず、当該プロジェクト内だけへ体験生として登録できます。
5. エラー0件を確認し「検証済み内容を反映」を押します。

反映すると、必要授業回数、全開校日・全有効コマの可否がまとめて登録されます。通常担当、
担当優先度、1対1必須は共通名簿の通常授業設定を使用し、アンケートから変更しません。
生徒・講師の回答原本と、赤・黄の要確認一覧を含む統合xlsxは`.jukuschedule`内へ保存されます。
必要な場合は「統合xlsxを保存」で外部へ取り出せます。

反映後に生徒の参加可否を調整する場合は、③画面右上の
「取込み済み回答を編集…」を使用します。

1. 学年で絞り込み、対象生徒を1名以上選びます。「表示中をすべて選択」で、同じ
   同じ変更を行う生徒をまとめて選択できます。
2. ①設定の開校日・休校日を確認し、編集する開校日を選びます。休校日は授業を
   配置しないため編集できません。
3. 各コマで「変更しない」「参加可」「参加不可」を選び、「変更を保存」を押します。

個別指導を入れない時間は「参加不可」にします。選択した全生徒へ
同じ変更を1トランザクションで反映します。「参加可」は値1として保存されるため、
元が「希望」（値2）のセルも通常の参加可能へ変更されます。

チェックボックス表で同日のZ・A・B・Cなどが1セルへカンマ区切りで入るのは正常です。
アプリが各コマへ分解するため、セルを分けたり列を追加したりしないでください。

時間割配置済みの講習では、受講希望の暗黙置換を防ぐため一括反映を拒否します。この場合は
現在の配置を安全に整理してから再取込みするか、次項の差分取込みを使います。

### 10.3 templateを出力する（独自様式・過去形式）

「アンケート取込み」から生徒用または講師用templateを出力します。

availabilityは次の3段階です。

| 値 | 意味 |
|---:|---|
| 0 | 不可 |
| 1 | 可能 |
| 2 | 希望 |

生徒templateには生徒ID、氏名、科目code、日付、各コマ、第1～第3希望講師、備考が
あります。講師templateには講師ID、氏名、日付、各コマ、備考があります。

通常担当、優先度5、1対1契約は塾側masterです。アンケート回答から上書きしません。

### 10.4 xlsx / CSVを個別に検証する

1. 「生徒回答」または「講師回答」を選びます。
2. xlsxまたはCSVを選びます。
3. 「回答ファイルを選ぶ」→「内容を確認する」→「反映完了」の表示に沿って進みます。
4. xlsxではsheet、CSVでは文字code（自動／UTF-8／CP932）を確認します。
5. 先頭previewを確認して「検証」を実行します。
6. error / warningと追加・変更・変更なし・削除候補を確認します。
7. errorを修正し、もう一度検証します。
8. 削除候補を削除する場合だけ、明示的に選択します。
9. 「反映」で保存します。

通常は列の対応設定を触る必要はありません。回答ファイルの列名が標準と異なる場合だけ、
「列名が合わない場合の設定」を開いて対応を確認します。

反映直前にfileを再読込みします。preview後にfileが変わっていた場合は反映しません。
名前が一致してもIDが異なる行を自動的に同一人物としません。

### 10.5 ④「事前確定」で個別指導の1枠を固定する

保護者との連絡などで、時間割作成前に日時と担当が決まった
授業だけを登録します。

個別指導の場合は次の順です。

1. 学年を選ぶと、その学年で未配置の受講希望がある生徒だけが表示されます。
2. 生徒を選ぶと、その生徒が受講予定の科目だけが表示されます。
3. 科目、担当講師、開校日、コマを選び、「この個別枠を固定」を押します。
4. 複数回を固定する場合は、同じ操作を必要な回数だけ繰り返します。

登録前に、生徒・講師の空き、講師資格、優先度5、同時最大2名、
1対1必須、連続上限、空きコマ等を通常の手動編集と同じ検証器で確認します。ハード制約に
違反する個別登録は保存されません。保存された個別枠は1対2の1席を使い、ロック済みAssignmentと
なるため、⑤の自動配置や再最適化で移動しません。後から変更・解除する場合は「時間割で
確認・変更」を開き、既存のロック・Undo / Redo・監査履歴の操作を使用します。

## 11. 集団授業

v1.6.0では集団授業の操作機能を一時的に停止しています。既存プロジェクトを壊さないため
保存構造のみ残しています。操作画面と登録機能はv2.0.0で再設計して追加します。

## 12. 入力検証

「未配置・警告」で保存済みprojectを再検証します。

- error: 最適化を開始できません。
- warning: 内容を確認します。最適化を禁止しない場合があります。
- info: 状態の案内です。

各行の「該当画面を開く」から、生徒、講師、アンケート、時間割、設定のうち
修正対象となる画面へ移動できます。移動後、表示された対象IDと内容を確認してください。

主なerrorは、未登録ID、時刻重複、期間外data、優先度5の通常担当不足、資格不足、
固定授業の衝突等です。行・列が分かる取込みerrorは元fileを修正して
再取込みします。

## 13. 時間割を自動作成する

1. 入力検証のerrorをすべて解消します。
2. 「時間割」を開きます。
3. 「ロック以外を再最適化」を選びます。
4. 対象Assignment、lock、未配置数を確認します。
5. checkpoint backupの作成に成功すると最適化画面へ進みます。
6. presetを選びます。

| preset | 時間上限 |
|---|---:|
| 高速 | 30秒 |
| 標準 | 120秒 |
| 高品質 | 600秒 |

7. 「自動作成を実行」を選びます。
8. status、配置／未配置、目的内訳、理由、warningを確認します。

表示されるstatus:

- `OPTIMAL`: 現在の最適化段階で最適性を証明。
- `FEASIBLE`: すべてのハード制約を満たす実行可能解。全段階の最適性は未証明。
- `INFEASIBLE`: model上の実行可能解なし。
- `UNKNOWN`: 制限時間等で解の保証がない。
- `MODEL_INVALID`: modelが不正。

`OPTIMAL`または`FEASIBLE`で、独立検証も通った非中止結果だけを時間割へ保存します。
制限を満たせないsessionは未配置になります。

### 中止

実行中に「中止」を選べます。強制終了ではなく安全な停止点でsolverを止めます。
中止したrunで現在のAssignmentを置き換えません。停止に時間がかかる場合も、Task
Managerから直ちに終了せず状態を確認してください。

## 14. 時間割を確認・編集する

時間割は左の未配置授業、中央の日付×コマ×講師grid、右の選択詳細・差分・履歴の
3ペインです。日付tab、前日／翌日、calendarで日付を移動します。
検索と学年・科目・1対1・優先度5・warning・lock・未配置filterを利用できます。

cardには生徒名、学年、科目と、1対1、優先度5、lock、手動変更、warning等を
色だけでなく文字・iconでも表示します。集団授業は重なるコマに別blockで表示します。

### 14.1 drag & drop

配置済みcardまたは未配置cardを別の日時・講師へdragします。

- 緑: ハード制約を満たし、悪化するsoft条件なし。
- 黄: ハード制約を満たすが、講師希望、希望日時、1対2、既存配置等が悪化。
- 赤: ハード制約違反または操作不正。適用不可。

黄は理由と前後値を確認し、変更理由を入力した場合だけ適用します。赤を管理者確認だけで
強制保存する機能はありません。

### 14.2 詳細編集

cardの詳細から日付、コマ、講師、lock、授業備考を編集できます。配置から未配置へ
戻す場合も理由を記録します。

操作時はpreview後、保存transaction内で現在DBを読み直して同じ検証を行います。
成功するとAssignmentとAuditLogを一緒に自動保存します。失敗時は両方をrollbackし、
「自動保存済み」と表示しません。

### 14.3 lockと再最適化

残したい授業を授業単位でlockします。lock済み授業は直接移動・未配置化できません。
解除は明示操作です。

「ロック以外を再最適化」は全体を再計算し、lock済みAssignmentだけをハード制約として
保持します。選択した日・生徒・講師だけの部分再最適化ではありません。

### 14.4 Undo / Redo

移動、配置、未配置化、lock、備考等をUndo / Redoできます。各逆操作もDBへ保存され、
AuditLogへ残ります。

Undo / Redo履歴は現在のapp process内だけです。再起動、project切替、明示再読込み、
外部変更検出時は安全のため消えます。AuditLogは残ります。

## 15. 未配置とwarning

「未配置・警告」または時間割の未配置panelで、必要回数、配置済み、不足、理由を
確認します。

主な理由:

- 共通空き時間なし
- 優先度5担当講師との共通時間なし
- 講師が科目未対応
- 1対1または定員
- 連続上限
- 生徒・講師の空きコマ
- 集団授業
- 固定授業
- 開校日不足

「単独配置可」は、現在の他のAssignmentを動かさず、そのsessionだけを1件追加して
全ハード制約を再検証した候補です。複数候補を同時に適用できることや、最適解を
保証するものではありません。

## 16. Excel / PDF / CSVを出力する

1. 「出力」を開きます。
2. 「最新dataを再読込み」を選びます。
3. 画面の「1. 出力対象」→「2. 形式」→「3. 保存先」の順に選びます。
4. 必要なら対象日、生徒、講師を絞ります。
5. 用紙、向き、日数、講師列数、文字、余白、表示項目を変更する場合だけ
   「詳細設定を開く」を選びます。
6. PDFは「印刷previewを更新」でpage、倍率、幅合わせを確認します。
7. 保存先を選び、出力します。必要なら「出力後に保存先フォルダーを開く」を選びます。

未配置が残っている場合は、件数と「未配置・警告を確認」が表示されます。未配置があっても
既存の業務仕様上出力可能な場合がありますが、配布前に必ず内容を確認してください。

| 帳票 | Excel | PDF | CSV |
|---|:---:|:---:|:---:|
| 全体時間割 | ○ | ○ | — |
| 生徒別 | ○ | ○ | — |
| 講師別 | ○ | ○ | — |
| 未配置・warning | ○ | ○ | — |
| 割当て生data | — | — | ○ |

実出力前に現在DBを読み直し、全Assignmentを独立検証します。ハード制約違反や参照欠落が
あれば出力しません。同名fileは確認なしに上書きせず、生成成功後だけ置き換えます。

Excelは編集可能です。PDFはA3 / A4、縦横に対応します。過密で読めない縮尺になる場合、
極小文字で成功させず、1pageの日数または講師列数を減らすようerrorを出します。
ロゴはPDF headerへ表示しますが、Excelへ画像として埋め込みません。

時間割表の狭いセルでは、生徒同士・講師同士で姓を比較します。同姓者がいなければ
姓だけ、同姓者が複数いれば該当者をフルネームで表示します。氏名に空白がない既存
データは安全に分割できないため、登録された氏名全体を表示します。生徒別・講師別の
本人見出しは取り違え防止のためフルネームです。

出力fileと印刷物には個人情報があります。共有folderの権限、印刷物の回収、廃棄方法を
確認してください。

## 17. 保存、別名保存、複製、backup

時間割の編集は操作ごとに自動保存されます。「手動保存」は未保存queueをcommitする
操作ではなく、現在の整合したSQLiteを別fileへbackupする明示保存点です。

- 名前を付けて保存: copyを作り、現在projectを新しいfileへ切り替える。
- 複製: copyを作るが、現在projectは切り替えない。
- backup: 整合したsnapshotを作り、現在projectは切り替えない。

接続中の`.jukuschedule`をExplorerで単純copyせず、appの操作を利用します。
古いschemaのprojectを開く際は、migration前に自動snapshotを作り、失敗時はmigrationを
始めません。

プロジェクトを開いた直後と、アプリ実行中の設定間隔ごとに自動backupを作ります。
既定は5分間隔・5世代です。利用者設定YAMLの`backup.automatic_interval_minutes`と
`backup.automatic_generations`で1以上の整数へ変更できます。

ホームの「バックアップとデータ整合性」では、次を行えます。

1. 「DB整合性を確認」で現在fileのSQLite整合性を検査する。
2. 自動、migration前、前回の復元前backupを日時と検査結果で確認する。
3. 整合性が確認できた候補の「復元」を選ぶ。
4. 確認dialogで復元対象を再確認する。
5. 復元後、project名、master、時間割、lock、警告を確認する。

復元は現在fileを即時上書きしません。選択backupを一時fileで検証し、既存の復元先を
必ず「復元前backup」へ退避できた場合だけ原子的に置き換えます。破損backupは復元
buttonが無効になり、任意のbackupは「別のバックアップを選んで復元」から選べます。

前回の正常終了を確認できないmarker、またはprojectのopen失敗がある場合、projectを
開いていなくてもホームに復旧対象と候補を表示します。復元候補がなくても元fileへ
汎用SQLite toolで修復SQLを実行せず、表示messageとlog時刻を記録してください。

すべてのbackupは暗号化されず、元projectと同じ個人情報を含みます。Windows accountと
folder権限で保護し、Git、公開issue、メールへ添付しないでください。

## 18. 終了と再読込み

1. 実行中の最適化・出力がないことを確認します。
2. form編集中の未保存状態がないことを確認します。
3. appを終了します。
4. 再起動後、「最近使ったproject」または「開く」から`.jukuschedule`を選びます。
5. project名、master、Assignment、lock、AuditLog、出力設定を確認します。

最適化・出力のworkerを強制終了しません。終了に時間がかかる場合は処理の完了または
安全な中止を待ちます。

## 19. 個人情報と安全な運用

- `.jukuschedule`、backup、log、input、outputをGit、issue、chat、public cloudへ
  添付しません。
- OS accountと保存folderのaccess権を限定します。
- backupにも元projectと同じ個人情報があります。
- screen shotやscreen recordingにも氏名・希望・担当が写ります。
- 問い合わせには、可能なら架空dataで再現し、app version、DB schema、error code、
  発生手順、logの必要部分だけを伝えます。
- log全体を外部送信する前に、pathや業務情報がないか確認します。
- appはauto updateしません。新versionは公式ReleaseとSHA-256を確認して入手します。
