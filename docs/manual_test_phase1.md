# Phase 1 手動確認手順

この手順はQML画面とWindows上の基本動作を確認するためのものである。業務データは
使用せず、Phase 2以降の機能が動作することは確認対象にしない。

## 前提

READMEの手順でPython 3.12の仮想環境と開発依存関係を準備する。

```powershell
python -m summer_scheduler
```

## 画面

1. ウィンドウタイトルが「夏期講習時間割作成」であることを確認する。
2. サイドバーに次の9項目が、この順序で表示されることを確認する。
   - ホーム
   - 生徒
   - 講師
   - 集団授業
   - アンケート取込み
   - 時間割
   - 未配置・警告
   - 出力
   - 設定
3. ホームに仮の講習サマリーと基盤ステータスが表示されることを確認する。
4. 各サイドバー項目を選択し、ホーム以外では対応する画面名、実装予定Phase、
   「現在は閲覧用プレースホルダー」の説明が表示されることを確認する。
5. 選択項目が背景色だけでなく、左インジケータと「選択中」の文字でも判別できる
   ことを確認する。
6. キーボードのTabキーでサイドバー項目へフォーカスでき、EnterまたはSpaceで
   選択できることを確認する。

## サイズと表示

1. 1366×768のWindows表示領域で主要なメニューとホーム内容を操作できることを
   確認する。
2. ウィンドウを最小サイズ付近まで縮め、内容が重ならず、必要な箇所をスクロール
   できることを確認する。
3. Windowsの表示倍率100%と150%で、日本語が欠けたり極端に小さくなったりしない
   ことを確認する。

## ローカル初期化

初回起動後、次を確認する。

- `%LOCALAPPDATA%\SummerScheduler\data\summer_scheduler.db` が作成される。
- `%LOCALAPPDATA%\SummerScheduler\logs\summer_scheduler.log` が作成される。
- DBに `alembic_version` と `application_metadata` の2表がある。
- リポジトリ内にDBやログが作成されない。

確認用のDBやログに実データを入力せず、不要になった確認用ファイルは利用者自身が
内容を確認してから削除する。

## 自動確認との分担

CIではoffscreen起動により、QML読込み、イベントループ終了、SQLite初期化、ログ生成を
確認する。見た目、キーボード操作、DPIはこの手順で確認する。Phase 2以降の業務規則は
QMLの目視確認ではなく、DomainおよびApplication Serviceの自動テストで検証する。
