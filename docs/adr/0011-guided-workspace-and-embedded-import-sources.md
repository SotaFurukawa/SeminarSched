# ADR 0011: フロー型UI・自動管理workspace・アンケート原本内包

- 状態: 採用
- 日付: 2026-08-07

## 背景

利用者が保存先や機能別メニューを理解してから作業する構成では、授業日設定、アンケート、
時間割配置、個人時間割出力の順序が分かりにくい。講習ごとのファイル選択を繰り返すと、
アンケート原本を移動・削除した場合に再確認も難しくなる。

## 決定

- ホームに4段階の業務フローを表示し、既存の各機能へ案内する。
- `%LOCALAPPDATA%/SummerScheduler/workspace`配下へ`生徒`、`講師`、`プロジェクト`を
  自動作成し、新規プロジェクトは`プロジェクト`へ自動保存する。
- 校舎はDB互換性のため内部既定値を保持するが、新規作成時の入力項目にはしない。
- 現在のプロジェクトを開いたまま次の講習を作る場合、生徒、講師、講師対応科目を継承する。
  講習ごとに異なる必要授業回数やアンケート回答は継承しない。
- 最後に反映した生徒・講師アンケート原本をBLOBとして`.jukuschedule`内へ保存する。
  同じ種別を再取込みした場合は、監査履歴を残しつつ原本snapshotを差し替える。
- 集団授業はカレンダー入力と従来のExcel一括取込みの両方を提供する。

## 理由

インストール先直下はWindowsの権限で書き込めない場合がある。利用者別データ領域なら
インストーラー版とポータブル版で同じ安全な保存規則を使え、通常はOSと同じCドライブに
配置される。SQLite単一ファイルへ原本を内包すれば、別フォルダのコピーよりプロジェクトとの
対応を保ちやすい。

## 影響

アンケート原本には個人情報が含まれるため、`.jukuschedule`、バックアップ、複製も同じ
アクセス制御が必要になる。原本の差替え後も`ImportBatch`と`AuditLog`は履歴として保持する。
