# ADR 0013: 科目区分の分割と後方互換移行

- 状態: 採用
- 日付: 2026-08-22
- 関連: ADR 0002、0005、0012

## 背景

小学校の算数・国語は、中学受験を指導できる講師と、それ以外を指導できる講師を
区別する必要がある。また高校数学の「数学一般」は、数学IAと数学IIBCを別の資格として
管理する必要がある。表示名だけを変えたり、片方の資格から他方を推定したりすると、
講師が実際には指導できない授業へ配置されるおそれがある。

一方、既存`.jukuschedule`では科目の内部IDがLessonRequest、TeacherQualification、
GroupLesson、RegularLessonProfileから参照されている。既存コードを削除して新規作成すると
これらの参照を破壊するため、互換移行が必要である。

## 決定

- 既定科目を小学校7、中学校5、高校14の計26科目とする。
- 既存コード`ES_MATH`は「小学校・算数（中学受験以外なら可能）」、`ES_JPN`は
  「小学校・国語（中学受験以外なら可能）」、`HS_MATH_GENERAL`は「高校・数学IA」へ
  名称変更する。内部IDと既存参照は保持する。
- `ES_MATH_ENTRANCE`、`ES_JPN_ENTRANCE`、`HS_MATH_IIBC`を新規コードとして追加する。
- 新規3科目のTeacherQualificationは既存資格から推定しない。講師本人または校舎側が
  明示的に設定する。
- Alembic `20260822_0009`で既存プロジェクトを同じ規則へ移行する。共通名簿Excelも
  「この講習へ反映」時に既定科目の名称と不足科目を補う。
- 利用者が追加した独自科目と、既定科目の有効／停止状態は保持する。

## 互換性と安全性

- migrationは既存科目行を更新するため、外部キーで参照されるIDを変更しない。
- downgrade時、新規科目が未参照なら削除する。参照済みならデータを削除せず使用停止に
  して保持する。
- 旧算数・国語を中学受験対応へ、旧数学一般を数学IIBCへ自動拡張しない。これは誤配置を
  防ぐための安全側の解釈であり、最適化のハード制約は変更しない。
- Googleフォーム、共通名簿Excel、例示データは同じ26科目の表示名を使用する。

## 影響

既存プロジェクトを1.3.1で開くとmigration前backupの後に科目マスターが更新される。
新設科目を利用する前に、講師ごとの指導可否と生徒の受講希望を明示的に確認する必要が
ある。1.3.0以前へ戻す場合、新設科目を参照するデータは削除されず、旧版で扱えない科目が
使用停止のまま残ることがある。
